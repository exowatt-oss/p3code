# OSS source-export test environment

The source export keeps upstream tests except for the synthetic-fixture exclusions in `exports/p3code.yml` (stored in the private export recipe) and the following conditional quarantine. These are not production-service tests. For a reproducible local run, use the pinned Node **26.12.1**, add `node_modules/.bin` to `PATH` for subprocess fixtures, set `TMPDIR` to a canonical path (`/private/tmp` on macOS), then run `vp test run --maxWorkers=4` from the repository root. The export build is also checked with `vp run typecheck` and `vp run --filter './apps/*' build`.

All environment-gated failures below were reproduced on the **pristine public upstream commit `3cd97a1ee2`** using this machine (macOS, APFS case-insensitive, Homebrew Git 2.56, Node 24.3), except the export-only workflow case. They are therefore not regressions introduced by P3's sanitization. Re-enable a gate when the upstream fixture is hermetic or the required runtime is present.

The `@t3tools/web (renders)` project is a render-performance profiler, not part of web's `test` script. It requires `T3CODE_RENDER_REPORT_DIR`; the 14 snapshot scenarios fail at pristine upstream without its dedicated metrics runner (and its old fake environment disagrees with current RPC). The export loads the project only when that variable is supplied, preserving `vp run report:renders` but excluding it from ordinary full tests.

The P3-specific Phi recommendation test was **updated**, not skipped: it now tests the neutral public baseline (`0.83.0`) rather than a private distribution build. Feads tests remain active with entirely synthetic actor, board, item and notification fixtures. On macOS with pinned Node 26.12.1 and Chromium, the one full-suite run completed **24,027 passed / 3 failed / 63 skipped** (24,093 tests). All three failures were fork-fixture drift, not upstream or environment failures: two mobile release-feed mocks still expected pingdotgg URLs, and the embedded triage playbook retained escaped `main` references when its canonical file used `oss/export`. Both are corrected in the export recipe. The affected-file rerun passed 62/62, and the public CI selection passed 255 with 7 skips; no full-suite failure remains unclassified.

The pre-commit `knip:check` gates unused **files and dependencies**. The source-only export retains the public API surface while private release workflows and packaging are absent, so the separate `knip:check:exports` audit currently reports 173 unused exports; it remains available for cleanup but is not a commit gate. Do not delete public API members merely to silence that audit.
